### [ChatGPT Work Explained: Cloud vs Local, Features, and Limits](https://simonwillison.net/2026/Aug/30/understanding-chatgpt-work/) ⭐️ 7.0/10

OpenAI&\#x27;s ChatGPT Work, announced July 9, is actually two products, according to Simon Willison: Work Cloud \(via chatgpt.com and mobile apps, also selectable in the desktop app\) and Work Local \(the desktop app formerly called Codex\). Work is limited to $20/month and up subscribers; free and $8/month Go users lack access. Work Cloud adds features missing from Chat: choice of GPT-5.6 Sol, Luna, or Terra \(plus GPT-5.5\) with reasoning levels up to Ultra, a code execution environment with internet access that defaults to open rather than an allowlist, a full headless Chrome browser that can fill forms, take screenshots, handle logins and 2FA without exposing credentials to the model, and run JavaScript via Playwright, plus a persistent filesystem, ChatGPT Sites publishing, sub-agents, and scheduled automations. Willison notes Work sessions appear billed against the Codex allowance, while Chat has a separate allowance and a Chat-only 5.6 Pro mode for $100/month subscribers.

rss · Simon Willison · Aug 30, 23:59

**「Background」** ChatGPT Work is OpenAI&\#x27;s task-oriented mode, positioned against Chat for open-ended conversation; OpenAI says to use Work when you want a completed artifact like a brief, deck, analysis, or workflow. The code-execution pattern dates to OpenAI&\#x27;s 2023 Code Interpreter, and Anthropic&\#x27;s Claude container has allowed restricted internet access since September 2025, but Work Cloud&\#x27;s default-open internet access is a notable expansion.

**「Impact」** For paid ChatGPT subscribers, Work Cloud turns ChatGPT into an agentic browser-and-code tool that can clone GitHub repositories, install dependencies, and interact with live websites, enabling tasks that regular Chat cannot perform because its container proxy blocks external access.
