### [Nolan Lawson asks why developers avoid native web platform APIs](https://nolanlawson.com/2026/10/03/why-dont-more-developers-use-the-platform/) ⭐️ 7.0/10

Nolan Lawson&\#x27;s essay asks why more developers don&\#x27;t &quot;use the platform,&quot; examining the persistent gap between native web platform APIs and framework adoption. The piece is an opinion/analysis article rather than a release, benchmark, or specification change, and it drew substantial Hacker News discussion with 251 points and 249 comments. **「Background」** “Use the platform” is a longstanding appeal from web standards, performance, and accessibility advocates—including essay author Nolan Lawson—for developers to build on native browser APIs rather than JavaScript frameworks. In practice, framework adoption has remained dominant: React is heavily preferred for the broader set of problems it solves, and even Web Components are often used through wrapper libraries such as Lit rather than directly. Much of the debate turns on whether native APIs are genuinely faster and better, or only in narrow cases where browser implementations are reliable enough to rely on.

**「Community discussion」** Commenters disputed the premise that native browser implementations are faster or better, citing inconsistent APIs such as &lt;datalist&gt; and arguing that Web Components are awkward enough that most usage happens through wrappers like Lit or larger frameworks. Others defended React as a relatively well-designed, not especially bloated library, while some said frameworks made tasks that were difficult and unreliable with platform APIs alone actually feasible.
